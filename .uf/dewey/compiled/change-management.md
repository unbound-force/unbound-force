# Change Management

## Current State (October 2026)

### Commit scope and staging

- Commit only files directly related to the active spec or change (AGENTS.md Commit Scope rule).
  Never `git add -A` or `git add .` on feature branches — stage files explicitly by path.
- Dewey learnings produced during a change's workflow are directly related to that change and ship
  with the feature PR. Tooling scaffolds (`uf init` sync, convention-pack updates, command-directory
  renames, schema template updates) go on a separate branch (e.g. `chore/uf.init-sync`).
- Each logically independent change gets its own branch with its own justification. Unrelated bug
  fixes found mid-change, reverts of prior features, and spec amendments are separate concerns:
  bundling them invites scope-creep findings and blocks independent revert. A revert not traced to
  the active spec's tasks.md is a commit-scope violation regardless of functional relatedness.
- The full working-tree diff against upstream/main is reviewed as if it were a single commit; a
  branch with zero unique commits is not exempt from scope analysis.
- Scaffold drift tests (TestEmbeddedAssets_MatchSource) enforce byte-identical sync between
  canonical command/template files and their internal/scaffold/assets mirrors; every canonical edit
  MUST be mirrored within the same change.

### Adopting drift and commit sequencing

- When a maintainer adopts pre-existing working-tree drift (e.g. a governance-gated
  pinned-dependency bump) into an in-flight spec change, the proposal must task commit sequencing
  explicitly: the spec-artifact commit excludes the adopted files (preserving the spec/implement
  phase boundary), and the gate-coupled lockstep set (manifest, scaffold mirrors,
  enforcement-test expectations, provenance testdata, AGENTS.md/README lines) lands as one atomic
  commit so no pushed commit leaves the pin-enforcement gate inconsistent (a manifest-vs-test-
  expectation mismatch fails `make check`).
- Commit the change's spec artifacts BEFORE adopted implementation commits — or rebase immediately
  while the branch is unpushed — so history preserves spec-before-implementation ordering. Repair
  is trivial pre-push (commit + rebase); unrecoverable once pushed.

### Artifact and checkbox reconciliation

- When work lands as a dedicated commit before tasks.md is authored or updated, reconcile the
  checklist against that commit's actual file set: grep tasks.md for unchecked items whose files
  appear in the commit's diff. Unchecked-but-complete markers are fail-closed drift (they block
  archive/resume gates) and reviewers must flag them.
- Tasks generated by tooling may reference external tools that do not exist in this repo (the
  openspec CLI's source lives elsewhere; it is invoked by `uf init` via initSimpleTool). Mark such
  tasks N/A and adapt them to what is implementable: .openspec.yaml, scaffold templates, and
  command files such as uf.finale.md.

### SHA citation hygiene

- Commit SHAs written into governance artifacts (CHANGELOG entries, spec annotations,
  proposal/design text) go stale the moment the feature branch is rebased: re-picked commits leave
  every in-repo citation pointing at a reflog-only orphan that will not exist on the merged PR,
  breaking rollback paths documented against those SHAs.
- At /uf.finale — or immediately after any rebase, while the branch is unpushed — grep the change's
  governance artifacts for hex SHA patterns and verify each with `git rev-parse --verify
  <sha>^{commit}`. Prefer describing lockstep commits by purpose in living documents; keep exact
  SHAs in the PR body, which can still be edited.

### Fix-loop claim invalidation

- Fix-loop iterations that adopt reviewer-requested refactors or doc corrections silently
  invalidate spec-artifact and CHANGELOG claims written against the base diff ("no existing X
  changes", "the only edit is Y", per-section enumerations). After every fix-loop commit, re-diff
  each enumerated claim against the cumulative base..head diff, and amend the unarchived OpenSpec
  delta (or add tasks) for any scope expansion before the next iteration or archive.
- A change's own factual claims must be true at merge (content pack FA-001). When reviewer
  feedback exposes a gap the CHANGELOG claims as covered, the spec-scope defense ("FR-NNN
  intentionally scoped the siblings to X") does not warrant deferral: either make the claim true
  by porting the already-shipped semantics — amending the unarchived delta so the port traces to
  spec — or correct the claim; deferring leaves a false changelog claim plus the gap.
