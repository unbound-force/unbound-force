Delegating PR-scope classification to a SHA-pinned external reusable workflow: the pin supplies the immutability an in-repo detector test used to provide, but the aggregate required-check only fails closed on *unexpected* code values. A code PR misclassified as skip (code=false) still turns the required aggregates green with the gated jobs skipped, because the aggregate expects skipped-when-false. The dangerous direction is not self-verifying. Keep skip predicates scoped to non-executable paths (learnings/markdown) or add a backstop that exercises both the true and false directions.
