When reviewer feedback cites the determinism rules (DE-001/DE-005) against newly added command prose but the maintainer explicitly scopes it "longer term", the coherent feedback-round resolution is ACCEPT-by-record: verify with gh issue list that no follow-up already exists, then record one consolidated follow-up in the repo's established "Create <tool> plugin tool" issue format, capturing the tool name, its return contract, its plugin-layer placement beside intent-level precedents (uf_unleash_branch_gate, resolve_base_ref), and the coupled updates the extraction increment must carry (byte-identical scaffold mirror, contract-test clause rewrites, DE-007 seam verification). This is preferable to implementing the tool inside the scoped bug-fix PR (commit-scope violation; the increment spans a new TypeScript tool, tests, and mirror collapse) and to dropping the item (untracked governance debt that keeps growing as dual-file prose edits). Parallel recommendations from the same feedback round targeting the same choreography (e.g., an architect's item-level finding) should be consolidated into the single record so one issue covers the accumulation.
