When a learning batch arrives with bodies truncated at the capture tool's preview cap (unbound-force: consolidate_dispatch's 512-character proposals preview) and the source sessions/dispatch artifacts are unrecoverable, the faithful repair is evidence-grounded reconstruction, not invention: preserve each verified truncated prefix verbatim, continue the sentence to an actionable close grounded in the public source findings that fragment-match the prefix (PR #949's inline review comments matched all 15 truncated bodies on PR #968), and end with terminal punctuation — the shape accepted for the identical defect on merged PR #949 (commit cd603598). Fidelity moves from byte-exactness to source-grounding; confining new text to the continuation keeps the original capture auditable. Spot-check the recovery constraint before choosing the approach: a Dewey keyword search for a truncated tail fragment confirms whether any indexed full-text copy exists. Detection-only commit gates catch this class too late — the follow-up should also fix the capture path (read full payload.proposals at store time), since the truncation is irreversible once the source session is gone.
