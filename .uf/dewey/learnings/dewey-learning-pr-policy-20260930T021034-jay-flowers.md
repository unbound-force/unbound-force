When codifying policy that affects commit scope or PR composition, embed the clarification directly in the existing behavioral rule rather than creating a new standalone section. Issue #570 revealed ambiguity in the Commit scope rule — reviewers interpreted "only files directly related to the active spec" as excluding Dewey learnings. The fix was a single clarifying clause within the existing rule, keeping the behavioral rules compact and ensuring readers encounter the guidance in context. This pattern (inline clarification over new section) should be preferred for similar policy gaps.
