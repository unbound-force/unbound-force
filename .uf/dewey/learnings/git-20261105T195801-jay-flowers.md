git fetch from a URL (as opposed to a named remote) writes only FETCH_HEAD and updates no remote-tracking ref; git status then cannot resolve an upstream — branch.<name>.remote set to a URL has no tracking ref — and reports no ahead/behind divergence. gh pr checkout produces exactly this state when the PR head is a fork not configured as a named remote. Divergence gates in command prose must compare explicitly against FETCH_HEAD (git rev-list --left-right --count HEAD...FETCH_HEAD) rather than relying on git status output, which only works for named remotes.
