Issues proposing to deduplicate command boilerplate into a skill must be triaged against Constitution Principle VI pattern-by-pattern, not wholesale. Judgment guidance (session-resume guards, re-confirmation instructions) has a sanctioned consolidation path — the command-prose-pilot "defined once, referenced by name" standard — but mechanically classified content does not: prescribed output templates (MANDATORY GATE banners with {context}/{options} slots) fall under determinism pack DE-003 tool-rendering (format_unleash_exit / unleash-deterministic-tools "Exit rendered verbatim" precedent), and fixed shell choreography (mktemp + chmod 600 + --input + rm -f injection safety) falls under DE-001 tool extraction, with existing tools (uf_finale_create_pr, fetch_failed_run_logs, build_review_prompts 0o600 artifacts) already owning part of that behavior. When a parent epic sequences prose consolidation (Phase 1) before tool extraction (Phase 2 — the unbound-force #659 pattern), a Phase 1 issue is only actionable when it explicitly frames the skill prose as an interim mitigation with a named Phase 2 extraction path; otherwise its acceptance criteria institutionalize prose as the mechanism of record, which surfaces as a CRITICAL-severity DE-003/DE-001 conflict at review time. Triage checklist for this issue class: classify each pattern deterministic vs. judgment (MP-022), require DE-004 measurable before/after deltas, and check for an overlapping active OpenSpec change (issue-level duplicate searches do not surface openspec/changes/ overlap).
