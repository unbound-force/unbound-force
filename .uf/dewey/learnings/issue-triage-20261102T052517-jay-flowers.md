Triage pattern for self-questioning cross-tool vocabulary issues: an issue observing ecosystem-level metadata divergence — each hero repo locally satisfying an org constitution provenance mandate with a different vocabulary (uf Envelope hero/version/timestamp; Gaze Metadata gaze_version/timestamp; Dewey source/indexed_at) — is a valid, objective enhancement even when it embeds "is this actually a problem?" uncertainty and calls the status quo "arguably correct". Validity anchors: (1) the divergent implementations are code-verifiable at citable file paths, (2) a concrete cross-tool consumer is named, (3) the constitution trade-off (Principle I/III self-describing provenance vs Principle II composability) is explicitly documented with options and a recommendation. These are design-decision issues, not questions or opinions; if the recommended option spans repos, the follow-up work routes to the strategic (Speckit) tier. Gotcha: hero constitutions may define mandated metadata in divergent local wording (Dewey Principle III provenance = source type/origin/timestamp/relevance vs the org's producer/version/timestamp/input), so the divergence surfaces mainly during cross-tool claim audits such as VISION.md verification.
