On quick/fix-review-submission-validation, root-caused and fixed the code-review-no-success stranding that hit the quick/accept-variantless-parent-model dispatch (correlation_id 32730f90-6358-4ab7-8c21-e70493a18fba): OpenCode 1.19.0 does NOT enforce plugin tool arg schemas host-side, so a plugin tool that persists child-submitted data MUST safeParse its args inside execute before storing anything. The submit_review_findings and submit_lesson_proposal tools trusted the host to validate, GLM 5.3 reviewer children submitted findings omitting the required severity key (and in another dispatch an extra unrecognized key — proving .strict() was not enforced either), the tools replied "N finding(s) submitted", and the invalid data only surfaced at finalize_review_dispatch's strict schema check — 12 invalid severity fields (6 findings x per-run + top-level), rejected three times, with the child sessions long gone and no retry possible. The fix: both submit tools now safeParse against their declared schemas and return a descriptive per-field error storing nothing (modeled on capture_review_diff's existing self-validation pattern), and consolidate_dispatch excludes schema-invalid harvested submissions with invalid_submissions_excluded warnings, plus run_findings_overflow and consolidated_findings_overflow cardinality caps mirroring the finalizer's .max(512) bounds and 20-line bounded diagnostics, so the emitted payload is always finalize-shaped by entry and by count. Broader lessons for authoring plugin tools in this repo: never trust host-side validation at a persistence boundary — declare the schema for the LLM's benefit, then re-parse at execute; and when building a defense-in-depth layer in front of a strict final gate, mirror the FULL downstream constraint set (shape AND cardinality), not just per-entry shape. The review-council fix loop also proved itself: the parent files the docs-gate tracking issue itself (children cannot create issues; #892 filed for this change), fix iterations delegate to cobalt-crush-dev then re-dispatch all included reviewers with a fresh correlation_id, and iteration 1 flipped REQUEST CHANGES (1 HIGH + 2 MEDIUM + 1 LOW) to APPROVE WITH ADVISORIES.
